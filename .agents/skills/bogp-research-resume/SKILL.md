# BOGP研究レジュメ

## 適用と既定値

このリポジトリで「レジュメを作成してください」「実験結果をレジュメにまとめて」などと依頼されたときに使用する。履歴書、英文翻訳だけ、スライド作成だけの依頼には適用しない。既定の出力は日本語のLaTeX本文とPDF。A4・10pt・2段組・である調を用い、初見の読者へ目的、設定、結果、考察が伝わるようにする。長さは内容に合わせ、指定がなければ8ページ以内を目安とする。以前の7ページ・8ページや実験設定・章数を固定条件にしない。

ユーザーの対象、読者、投稿様式、ページ数、言語、編集対象の指定が優先される。新規文書は`notes/<topic>_resume_<YYYYMMDD>.tex`と同名PDF、図表は`notes/figures/<topic>_<YYYYMMDD>/`へ保存する。同名成果物がある場合、更新指示がなければ版名を付けて保持する。

## 作業の進め方

1. **根拠を確認する。** 対象の研究ノート、実験設定、実行・集計スクリプト、元の世代・制御履歴、集計JSON、文献メタデータを読む。対象が複数考えられるときは記録から候補を絞って質問する。レジュメ作成だけを理由にGP実験を再実行したり、制御器や実験条件を変更したりしない。
2. **記録と数値を照合する。** 比較手法、問題、反復数、分割、前処理、初期化、ウォームアップ、評価区間、評価予算を確定する。主要な表・グラフ・主張を元記録へ対応づける。平均・標準偏差の定義、欠測、対応比較の単位を確認し、可能な主要指標は再計算する。集計と元記録が矛盾する場合は都合のよい方を採用せず解消する。
3. **本文と図表を作成する。** 研究の目的と今回の問い、必要な手法・指標の簡潔な定義、実験の設定、結果、考察・限界、次の検証を自然な順でまとめる。問題選定が対象なら問題の意味、選定理由、出典、移植条件、注意点も含める。指定された内容に必要な章だけ置く。
4. **文献を追跡可能にする。** `references/reference_workflow_spec.md`に従う。保存済み本文を確認して再利用し、新たな設計主張に根拠が必要なら文献調査を行う。論文内は`\cite`と`\bibitem`による番号を使い、どの設定・説明がどの論文の節・表・図に基づくかを明記する。研究ノートの`[Rxx]`との対応を記録し、未取得原典の内容を確認済みとして引用しない。
5. **PDFを確認する。** 下記のコンパイル補助を使うか同等の確認を行う。最終本文をコンパイルして参照が解決するまで確認し、ページ数と警告を調べる。PDF全ページをPNG化して実際に見る。図、表、式、凡例、文字、見出し、改ページの切れや重なりを修正する。コンパイル成功だけをレイアウト確認の代わりにしない。
6. **共有と作業記録を整える。** PDF・TeXを示す。別環境での編集や共有が有用なら、本文、必要な図、生成済み表、再コンパイル手順を相対配置でZIPにする。LaTeX中間ファイルや元データ全部は入れない。`notes/research_note.md`へ何をしたか、理由、根拠ファイル、検証、残る制約を追記する。既存成果物は保持し、コミット・pushを自動では行わない。

## この研究で特に注意すること

- 「観測なしBO」は状態を代理モデル入力へ入れない非文脈BOを指す場合がある。報酬観測や状態計測まで省かれたかは実装で確認する。状態入力の比較と計測コストの比較を混同しない。
- HVはアーカイブ、多様性・平均木サイズは現在集団という分担を実装で確認する。HVの高さ、予測誤差、真の式の復元、構造多様性はそれぞれ別の性質である。
- 世代数はウォームアップと本評価を区別する。子集団評価のみか初期集団評価込みか、追加の検証・テスト評価を含むかを記載する。更新周期`k`と親選択のトーナメントサイズを混同しない。
- 反復回数とデータ分割数を区別し、同じ乱数シードの対応比較、平均差、標準偏差、信頼区間、有意差、同等性をそれぞれ区別する。少数回の予備観察から統計的優位を主張しない。
- 報酬式は実験時の設定・コードに合わせる。古い仕様メモの式で現在の実験を説明しない。多様性目標との一致項は、多様性の単純最大化ではない。
- 平均性能と実行間の安定性を分けて説明する。少数の大きな失敗、操作率、`k`、更新回数の違いによる説明は、観察結果と因果仮説を区別する。過去の有望性を新しい結果で裏付けずに再掲しない。
- 「Pareto archive」「warm-up」「seed」は本文では「パレートアーカイブ」「ウォームアップ」「乱数シード」に統一する。実験反復は「実行回数」。GP・BO・HV・EI・NRMSE・NSGA-IIと固有名・書誌情報は必要に応じて保持する。
- 図はMatplotlib等で元記録から再生成する。各曲線・点・帯・境界の意味を凡例・キャプションで示す。読み取りだけでなく、図から分かる結果と限界を書く。既存画像を修正するときは参照パスと他資料への影響を確認する。

## 書式と再利用元

最小のLaTeXひな型は[assets/resume-template.tex](assets/resume-template.tex)。プレースホルダーを埋め、必要な図表・節だけ追加する。

完成例と数値照合・図表作成の参考は[references/example-workflow.md](references/example-workflow.md)。実験結果を扱う場合や書式の判断に迷う場合に読む。例の実験名・日付・結果・絶対パスは新しい文書へ引き継がない。

## コンパイル補助

リポジトリのルートから以下を実行する。新規文書は新しい名前を使う。

```bash
.venv/bin/python .agents/skills/bogp-research-resume/scripts/compile_and_render.py notes/<topic>_resume_<YYYYMMDD>.tex --max-pages 8
```

補助はリポジトリ内のLuaLaTeX（なければPATH上のLuaLaTeX）で2回コンパイルし、最終ログを調べ、Popplerの`pdfinfo`・`pdftoppm`でページ数取得と描画を行う。ユーザーが別のページ上限を指定したら`--max-pages`を変える。描画後の画像は必ず目視する。依存ツールが不足していたら利用可能なランタイム・TeX環境を確認し、未完了の確認を説明する。
