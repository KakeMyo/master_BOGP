# 研究計画ブラッシュアップ: 文脈付き BO による GP 操作率制御

- 作成日: 2026-04-21
- 対象ノート: `notes/research_note.md`
- 参照ルール: `references/reference_workflow_spec.md`

## 1. 研究の再定義

本研究は、遺伝的プログラミングにおける交叉率 `p_c` と突然変異率 `p_m` を、固定ハイパーパラメータではなく、進化状態に応じて更新される制御入力として扱う研究である。

より論文らしく表現するなら、主題は次のように置く。

> GP の操作率を、進化状態を文脈とする閉ループ制御問題として定式化し、文脈付きベイズ最適化によって区間ごとに調整する手法を提案する。

この言い方にすると、「BO でパラメータを探す」だけの研究ではなく、次の 3 点を含む研究として見せやすい。

- 進化過程は非定常であり、同じ操作率でも探索初期、停滞期、収束期で効果が変わる
- GP 側の状態を観測し、その状態を条件に操作率を選ぶ必要がある
- 最終性能だけでなく、多様性維持、停滞回避、bloat 抑制も制御の対象に含める

## 3. 提案手法のブラッシュアップ

提案手法は、次の 4 部品として整理するとよい。

### 3.1 観測

GP の進化状態を、次の文脈ベクトルとして観測する。

$$
c_t =
\left[
\tau_t,\;
\widetilde{HV}_t,\;
\widetilde{\Delta HV}_t,\;
D^{\mathrm{struct}}_t,\;
\widetilde{s}_t,\;
\widetilde{b}_t
\right]
$$

この構成の狙いは、探索段階、性能水準、改善速度、構造的な探索性、停滞、木肥大化を小さい次元でまとめることである。

### 3.2 制御

BO は現在の文脈 `c_t` と操作率 `u_t = (p_c, p_m)` から区間報酬 `r_t` を予測する。

$$
r_t = g(c_t, p_c, p_m) + \varepsilon_t
$$

ここで重要なのは、`p_c` と `p_m` だけを最適化するのではなく、「現在の状態ではどの率がよいか」を選ぶ点である。これが文脈なし BO baseline との差分になる。

### 3.3 報酬

区間報酬は、HV 改善を主軸にしながら、多様性、停滞、bloat を補助項として扱う。

$$
r_t =
w_{hv} \widetilde{\Delta HV}_t
+ w_d S_D(D_t,\tau_t)
- w_s S_{\mathrm{stag}}(s_t)
- w_b S_{\mathrm{bloat}}(b_t)
$$

この報酬は「最終性能だけを追う制御」ではなく、「探索過程の状態も含めてよい制御を定義する」ためのものとして説明する。

### 3.4 制約

操作率には範囲制約と更新幅制約を入れる。

- `p_c in [0.55, 0.95]`
- `p_m in [0.01, 0.30]`
- 必要に応じて `p_c + p_m <= 1.0`
- 前区間からの変化量を制限する

これは BO の自由探索を完全には縛らず、進化過程の急変を避ける安全策として位置づける。

## 4. 研究質問の整理

今後の実験は、次の研究質問に答える形にする。

| ID | 研究質問 | 対応する実験 |
|---|---|---|
| RQ1 | 提案法は固定率 GP より最終性能または HV-AUC を改善するか | 固定率 baseline との比較 |
| RQ2 | 文脈付き BO は文脈なし BO より安定してよい率を選べるか | contextual / non-contextual BO 比較 |
| RQ3 | 構造多様性、停滞、bloat は制御判断に効いているか | 文脈・報酬 ablation |
| RQ4 | 学習された操作率時系列は探索段階ごとに解釈できるか | `p_c`, `p_m` の時系列可視化 |
| RQ5 | BO の計算オーバーヘッドは性能改善に見合うか | 実行時間と評価回数の比較 |

特に重要なのは RQ2 である。ここが通ると、本研究の中心である「文脈を見る意味」を直接示せる。

## 5. 先行研究上の穴

既存文献は、構造多様性、意味多様性、bloat、多目的 GP の根拠としては役立つ。一方で、参考文献取得ルールに照らすと、次の文献群がまだ弱い。

| 優先 | 必要な文献群 | 目的 |
|---|---|---|
| 高 | GP の adaptive operator probability / parameter control | 固定率から動的制御へ進む必然性を示す |
| 高 | evolutionary algorithm の parameter control / online configuration | 本研究を既存のパラメータ制御研究の中に位置づける |
| 高 | contextual Bayesian optimization | 文脈付き BO の理論的・方法論的根拠にする |
| 中 | BO による evolutionary algorithm tuning | 文脈なし BO baseline の妥当性を支える |
| 中 | EC/GP の統計比較方法 | run 数、検定、効果量、信頼区間を設計する |
| 中 | stagnation detection / restart / diversity recovery | 停滞指標と突然変異率再上昇の説明を強化する |

次回の文献追加では、この表をそのまま調査キューとして使う。

## 6. 実験計画の再構成

実験は、段階を分けて進める。

### 段階 A: 文献補強

目的は、提案法の新規性と比較対象を曖昧にしないこと。

- adaptive GP operator control の中核文献を追加する
- evolutionary parameter control / online algorithm configuration のレビューを追加する
- contextual BO の基礎文献を追加する
- 各文献を `[Rxx]` で採番し、どの研究質問に対応するかを記録する

完了条件:

- A: 中核文献が少なくとも 3 本追加されている
- B: 設計根拠文献が少なくとも 2 本追加されている
- `references/README.md` と `notes/research_note.md` が同時に更新されている

### 段階 B: toy engine で比較実験を作る

目的は、実 GP 接続前に制御器と比較枠組みを固めること。

比較対象:

- 固定率
- 手設計スケジュール
- ランダム制御
- 文脈なし BO
- 文脈付き BO

記録する指標:

- 最終 HV
- HV-AUC
- 停滞回数
- 平均多様性
- 平均木サイズ
- `p_c`, `p_m` の時系列
- 実行時間

完了条件:

- 同じ seed 群で全 baseline を走らせられる
- 結果が CSV または JSONL に残る
- 最低 5 seed の小規模比較ができる

### 段階 C: 実 GP へ接続する

目的は、toy engine の仮想的な挙動ではなく、実際の GP 集団で文脈指標と報酬を測ること。

最初の問題設定:

- 記号回帰
- 目的 1: 予測誤差
- 目的 2: 木サイズ
- 多目的評価として HV を使う

実装上の要点:

- DEAP 個体から prefix token を生成する
- `population_structural_diversity` を実集団に接続する
- 区間ごとに HV、多様性、停滞、木サイズを保存する
- toy engine と同じ `ClosedLoopRunner` のインターフェースに合わせる

完了条件:

- 1 問題、1 seed で最後まで走る
- 各制御区間の文脈、操作率、報酬が保存される
- 固定率 baseline と提案法の最小比較ができる

### 段階 D: ablation と統計評価

目的は、提案法のどの要素が効いているかを示すこと。

ablation:

- 文脈なし BO
- `tau + HV + DeltaHV` のみ
- 構造多様性あり
- 停滞あり
- bloat あり
- 全文脈あり
- HV のみ報酬
- HV + 多様性報酬
- 全項入り報酬

統計評価:

- 複数 seed
- 同一評価回数予算
- 平均、中央値、信頼区間、効果量
- 最終 HV と HV-AUC を主指標にする

## 7. 成功条件

本研究が十分に成立したと言える条件は、次のいずれかを満たすことである。

- 固定率または手設計スケジュールより、最終 HV または HV-AUC が改善する
- 最終性能が同程度でも、run 間ばらつき、停滞頻度、平均木サイズが改善する
- 文脈なし BO より、停滞時や多様性低下時の操作率変更が説明しやすい
- ablation によって、構造多様性、停滞、bloat の少なくとも 1 つが制御判断に寄与すると示せる

失敗時も研究として使える条件:

- 文脈付き BO が改善しない場合でも、どの文脈または報酬項が不安定化の原因かを示せる
- BO の観測数不足が原因なら、制御区間、warmup 点数、入力次元の感度分析としてまとめられる
- bloat 抑制が性能低下を招く場合は、性能と複雑度のトレードオフとして議論できる

## 8. 論文構成案

論文や卒論に落とす場合は、次の流れが自然である。

1. はじめに
   - GP の操作率は探索挙動を左右する
   - 固定率では進化状態に応じた調整ができない
   - 本研究では文脈付き BO による閉ループ制御を提案する

2. 関連研究
   - GP と操作率
   - 進化計算の parameter control
   - Bayesian optimization / contextual BO
   - GP の多様性、bloat、多目的評価

3. 提案手法
   - 閉ループ構造
   - 文脈ベクトル
   - 報酬関数
   - BO モデル
   - 操作率制約

4. 実験設定
   - 問題設定
   - baseline
   - 評価指標
   - seed、評価回数、統計比較

5. 結果
   - 最終性能
   - HV-AUC
   - 多様性、木サイズ、停滞
   - 操作率時系列
   - ablation

6. 考察
   - 文脈を見ることの効果
   - どの文脈が効いたか
   - BO の観測数と計算負荷
   - 失敗例と制約

7. 結論
   - 貢献の整理
   - 今後の拡張
